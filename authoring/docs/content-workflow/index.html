Freeze intake

Turn an approved curriculum slice into a stable, reviewable content plan before learner bytes exist.

Inputs
Locked curriculum/calendar snapshots, approved scope, official versioned documentation, day blocks.
Outputs
Course/module/topic manifests, draft objectives, artifact/lab applicability, minute budgets, intake and source snapshot evidence.
Owner / role

Content planner/author proposes; fresh education and SME critics still review intake evidence independently.

Tools

pep new-topic; the approved calendar extractor only when an approved source update exists.

Quality checks

T01 schema, T14 timing policy, T19 snapshot integrity; pending artifacts remain absent, never placeholder files.

Evidence

authoring/evidence/<course>/intake.md, source-snapshot.json, curriculum lock and hashes.

Common failure / rework

Unfrozen versions or an honest timing overflow return to intake. The gate reports pacing conflict; it never compresses minutes to pass.

Canonical source

workflow.md §2.1, validators.md, curriculum lock.

Instruction / prompt anchor

Tracked excerpt: “Fix the course slice from the curriculum, the module map, the topic list and draft objectives … Freeze the official source list per topic.”

Prompt status: no standalone intake prompt file is tracked.

105T19 proves all 105 calendar topic lists equal the simplified curriculum lists in order. This is snapshot integrity, not authored-topic count.

Map the canonical design

Give each course, module and topic one stable identity and one place in the learner tree and path-isomorphic catalog.

Inputs
Frozen intake, objectives, applicability decisions, prerequisites and curriculum pointers.
Outputs
course.json, module.json, topic.json; ordering in manifests; explicit present/absent declarations.
Owner / role

The scoped course or module author; branch ownership prevents parallel edits to one manifest or lock.

Tools

authoring/tools/pep new-topic course/module/topic creates catalog metadata without a learner placeholder.

Quality checks

T01 schema, T02 tree, T04 completeness, T05 manifest/files and T19 curriculum joins.

Evidence

Path-isomorphic catalog files and schema-valid objective, timing, freshness, licensing and companion fields.

Common failure / rework

A directory prefix used for ordering, a stray topics/ level, or an undeclared file returns to the manifest/tree design.

Canonical source

authoring/AGENTS.md, repository map, schemas.

Instruction / prompt anchor

Tracked excerpt: “Ordering belongs in manifests, not directory-name prefixes.” A pending topic lives in the catalog without an empty learner directory.

Prompt status: no design prompt file is tracked.

9 · 36 · 249Current tracked catalog: courses · modules · topics. Generated from manifests; it does not claim those topics are all authored.

Author artifacts

Build the primary standalone HTML, then only the companion branches that the topic declares and the curriculum supports.

Inputs
Topic manifest, objectives, frozen sources, HTML and lab contracts, shared component versions.
Outputs
Primary artifact.html; deterministic Markdown; applicable PDF/GIFT/video; topic/module/course lab where justified.
Owner / role

One author context per module writes topics in order and runs local gates, but never approves its own output.

Tools

md-from-html.mjs, pdf-from-md.mjs, GIFT validator and versioned fragments under components/.

Quality checks

T08 static HTML, T09 offline, T10 sandbox, T11 behavior, T12 accessibility, T13 responsive, T16 GIFT, T18 companions, T20 standalone, T24 component drift.

Evidence

Artifact bytes, topic manifest declarations, QA paths and later hash-bound review/source records.

Common failure / rework

Runtime sibling/network dependency, inaccessible controls, dishonest simulator behavior or placeholder companions return to authoring before review.

Real branches

Standalone companions; language-native lab bundle; optional video; Archify SVG for authoring/docs only—never learner runtime.

Instruction / prompt anchor

Tracked excerpt: “An HTML learner page is one plain HTML file. It embeds all required CSS, JavaScript, data, and accessible visuals.”

Prompt status: the repository names the authoring standard, but tracks no standalone author prompt or model transcript.

26 / 249Catalog topics with current HTML / all catalog topics. Companions currently include 26 Markdown, 6 PDF, 24 GIFT and 24 video records.

Bind provenance

Make every technical claim and optional media record inspectable against current bytes and named official sources.

Inputs
Final candidate artifact bytes, official URLs/sections, retrieval results, optional public video metadata.
Outputs
sources.json, optional video.json, retrieval dates, HTTP outcomes, response and artifact SHA-256 bindings.
Owner / role

Author prepares receipts; technology SME independently verifies technical claims and freshness.

Tools

check-links.mjs course/module/topic and check-video.mjs course/module/topic are explicit network commands; normal checks stay offline.

Quality checks

T15 requires current artifact binding, HTTP 200 and ≤30-day receipts. T17 separately checks video receipt binding, oEmbed and runtime budget.

Evidence

Topic evidence directory, source sections used, checked time, final URL/status and byte hash. Raw fetched pages are not committed.

Common failure / rework

A changed artifact stales its receipt; a rolling or unreachable source must be refreshed or honestly marked unverified—not silently badged verified.

Canonical source

validators.md T15/T17, workflow evidence rules.

Instruction / prompt anchor

Tracked excerpt: “Every technical claim traces to a source record … fetched live from official documentation with a retrieval date.”

Prompt status: verification behavior is executable and documented; no private SME prompt is exposed.

5 + 5Worked example: 5 source receipts and 5 video receipts, one per Linux Foundations topic.

Run deterministic gates

Exercise the final bytes locally with the same repository interface CI uses, except the explicitly private lab solved-run.

Inputs
Catalog, learner files, evidence, schemas, generated locks, QA paths and frozen curriculum snapshots.
Outputs
Test and check results; ignored QA diagnostics on failure; no status is inferred from a prose report.
Owner / role

The author runs local gates; CI reruns them. Machine checks block but never substitute for independent critics.

Tools

npm test, pep migrate-catalog --check, npm run check; targeted diagnosis via pep check --only TNN.

Quality checks

Schema, tree, lock, forbidden content, offline, sandbox, behavior, accessibility, responsive, timing, sources, GIFT, video, companions, lab, diagrams, licensing and critic gate.

Evidence

Command exits and CI checks; screenshots/traces stay ignored diagnostics or CI artifacts, never committed source.

Common failure / rework

Fix the authoritative input, regenerate derived artifacts/locks, and rerun. Never loosen timing, freshness or accessibility thresholds to force a pass.

Canonical source

workflow §2.5, pep CLI, CI workflow.

Instruction / prompt anchor

No generative prompt owns this stage. The tracked CLI and check modules are the behavior authority.

Core command: npm test && authoring/tools/pep migrate-catalog --check && npm run check.

18 → 2218 conceptual gates in the workflow contract, implemented by 22 current T*.mjs check modules.

Obtain dual independent review

Apply two different lenses to the same bytes without giving critics the author transcript or permission to self-approve.

Inputs
Artifact bytes, manifests, intake and frozen source list—never the author's transcript.
Outputs
Education and SME critic JSON with role, finding IDs, severity, locations, claims, evidence, recommendations and reviewed hashes.
Owner / role

Fresh education critic and fresh technology-SME critic, independent of the author and each other.

Tools

Critic report schema, evidence bindings and T25 coverage logic. The SME fetches live official documentation during review.

Quality checks

Education checks objective alignment, teach/practice shape, feedback, load, timing and accessibility. SME checks claims, commands, versions, fidelity, security and freshness.

Evidence

critic-education.json, critic-sme.json and current SHA-256 bindings to each reviewable file.

Common failure / rework

No independent critic means pause. Missing or stale role coverage fails T25; one critic cannot stand in for both roles.

Canonical source

workflow §2.3, evidence contract, critic schema.

Instruction / prompt anchor

Education safe excerpt: objectives, teach-before-use, cognitive load, retrieval, feedback, timing and accessible instructions.

SME safe excerpt: every technical claim, command, flag, default, simulator fidelity, real toolchain, security/privacy and source freshness.

Prompt status: these tracked role contracts are canonical; no standalone critic prompt file is tracked.

2 rolesEach reviewable file needs current education and SME coverage. The worked module's initial pair reported 6 findings.

Reconcile, correct and recheck

Turn findings into accountable decisions, then prove accepted corrections against new bytes within a bounded loop.

Inputs
Both critic reports and their byte hashes.
Outputs
Non-author reconciliation; corrected artifacts; same-role recheck items bound to current hashes; escalation where needed.
Owner / role

A non-author reconciler decides. The author fixes accepted findings. Relevant critics recheck their findings.

Tools

Reconciliation schema, recheck records, lock bindings and pep check --only T25.

Quality checks

Every finding has a decision. Critical/high accepted items need current same-role resolved rechecks; escalated/open items stay open.

Evidence

reconciliation.json, role-specific *-recheck.json, decision rationale and corrected-file hashes.

Common failure / rework

One loop runs at a time. A second is allowed once. A third correction loop is prohibited: escalate rather than churn or self-close.

Canonical source

workflow §2.4, review evidence, T25 implementation.

Instruction / prompt anchor

Tracked decision vocabulary: accept, reject-with-evidence, or escalate, each with rationale.

Prompt status: no standalone reconciliation prompt is tracked; schemas and gate behavior are authoritative.

5 → 1 → 0Worked module: 5 resolved and 1 open after first recheck; second bounded cycle closes all 7 unique findings; no third cycle.

Reconcile catalog and locks

Make declarations, learner files and review evidence agree, then regenerate scope-local integrity records.

Inputs
Final catalog metadata, learner bytes and evidence subtree for the course or module scope.
Outputs
Byte-identical regenerated module.lock.json or course.lock.json, including current/stale evidence bindings.
Owner / role

The scoped author regenerates; tools compute. Locks are never hand-edited and parallel module work never shares one module lock.

Tools

authoring/tools/pep lock <course>/<module> or course scope.

Quality checks

T04/T05 reconcile declarations and files; T06 compares lock regeneration byte-for-byte; T25 rejects stale critic coverage.

Evidence

Generated file inventory plus each review hash's resolved target and current state. Historical stale records remain visible.

Common failure / rework

Changed bytes stale review/source bindings. Refresh the owning evidence or review; do not erase history to make the lock look current.

Canonical source

evidence + lock behavior, lock implementation.

Instruction / prompt anchor

No model prompt: lock generation is deterministic. Tracked rule: T06 requires byte-identical regeneration while T25 separately requires current review coverage.

74Tracked file records in the worked example's current module lock. Binding counts are not presented as quality scores.

Open a focused PR and pass CI

Keep review ownership legible by changing one module, course scope or tooling scope—never a mixture.

Inputs
Delivery-ready final bytes, current evidence and regenerated locks on a focused branch.
Outputs
Non-draft pull request, reproducible CI result and human approval before merge.
Owner / role

Branch author opens the PR; CI validates; an approver controls merge. The author does not treat an open PR as landed.

Tools

Git/GitHub plus root package scripts. CI installs pinned Node/Playwright and Poppler, then runs the repository command interface.

Quality checks

npm test, migration check and npm run check on Ubuntu; approval remains mandatory after green checks.

Evidence

PR diff and checks bound to its commit. QA screenshots/traces upload only on CI failure and expire after seven days.

Common failure / rework

Mixed branch scope or a lock collision requires splitting/rebasing; a failed check returns to its owning earlier stage.

Canonical source

workflow §4, CI source, package scripts.

Instruction / prompt anchor

No PR-writing prompt is canonical. Tracked branch scope and CI source define what may ship and what is rerun.

3 commandsCI's repository gate interface: tests, migration check and complete checks. A green run is still not merge approval.

Hand off neutrally

Package learner-safe tracked material for the platform owner without pretending this repository publishes it.

Inputs
Landed learner artifacts or lab bundle; private staging only where explicitly required and never committed.
Outputs
Ignored neutral course export or checksummed lab bundle; platform owner receives separately managed private material where applicable.
Owner / role

Repository delivery owner exports; platform owner adapts, uploads and confirms outside this repository.

Tools

pep export [course] and pep export-lab <lab-id>; output stays under ignored build/.

Quality checks

Export allowlist excludes evidence and secrets. Lab export scans forbidden names and writes LAB_BUNDLE.sha256.

Evidence

Tracked source, prior gates and generated bundle inventory. Platform-only staging is retired after confirmed upload.

Common failure / rework

A missing bundle file returns to lab authoring. Platform conversion issues return through the platform owner; they are not silently patched into a second content tree.

Canonical source

lab handoff contract, export implementation, delivery scope.

Instruction / prompt anchor

No platform prompt or adapter is tracked because the platform contract is out of scope. The repository promises a neutral export, not publication.

UnavailableUpload, platform acceptance and publication outcomes are not tracked here. Do not convert absence of telemetry into success.
