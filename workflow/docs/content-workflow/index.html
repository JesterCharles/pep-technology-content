03

Create

Build accurate, accessible learner material and authentic practice.

What happens
The standalone HTML lesson is authored first; declared text alternatives, formative questions, video records and labs follow where they add learner value.
Why learners benefit
The lesson teaches before it checks, works offline and offers accessible feedback plus practice that uses the real toolchain.
What proves quality
Declared formats, deterministic companions, QA paths and public lab tests describe exactly what the learner can use.

Linux Foundations: five topics produce 21 learner artifacts—5 HTML, 5 Markdown, 1 PDF, 5 GIFT and 5 video records.

Inspect formats, ownership and exact checks
Formats when useful
  • Standalone Markdown, PDF and formative GIFT when declared.
  • A language-native lab only when authentic practice earns its setup.
  • A video record only after its content is verified.
  • Archify assets remain documentation, never learner runtime.
Owner

The content author creates topics in learning order and runs local checks, but never approves the same material independently.

04

Verify

Bind claims to current sources and exercise the artifact as a learner will use it.

What happens
Source and optional video receipts are bound to artifact hashes; local tests check content structure, behavior, accessibility, timing and offline operation.
Why learners benefit
Technical guidance is current, interactions work, and the experience remains usable across devices and constraints.
What proves quality
Fresh source receipts, declarative QA paths and passing command exits prove more than a prose status claim.

05

Review + improve

Apply independent teaching and technology judgment, then close accepted findings within a bounded loop.

What happens
Education and technology critics review the same final candidate; a non-author reconciles; the author corrects; relevant critics recheck fresh hashes.
Why learners benefit
Both how the material teaches and whether its technology is correct receive independent scrutiny.
What proves quality
Hash-bound reports, non-author decisions and same-role rechecks show who found, accepted and resolved each issue.

Linux Foundations: 7 accepted findings move from 5 resolved / 1 open after the first recheck to 7 resolved / 0 open after the second; no third cycle is used.

Inspect roles, loop rules and exact checks
Two independent lenses

Education checks objective alignment, teach-before-use, practice, feedback, cognitive load, timing and accessibility. The SME checks claims, commands, versions, fidelity, security and source freshness.

Accountable roles

Critics are independent of the author and each other. A non-author chooses accept, reject-with-evidence or escalate. The author fixes; the owning critic rechecks.

Bounded return

One correction loop runs at a time. A second is allowed once. Work escalates before a third loop rather than churning or self-closing.

Exact gate

T25 requires current education and SME coverage, reconciliation for every finding and zero open critical/high findings. Machine checks complement—not replace—judgment.

Prompt anchors, review state and canonical sources
Safe role anchors

Tracked workflow sections define both critic lenses and reconciliation vocabulary. No standalone critic or reconciler prompt file is tracked; hidden prompts and author transcripts are not inferred.

Independently reviewed means

Current education and SME evidence covers every reviewable file; each finding has a non-author decision; no critical/high item remains open. It does not imply all deterministic gates pass or approval exists.

06

Ready

Confirm that the reviewed learner-content package and its evidence describe the same exact bytes.

What happens
Artifact declarations, source receipts, deterministic results and independent rechecks are reconciled into one internally consistent content package.
Why learners benefit
Only material whose claims, interactions, practice and review evidence still agree is marked ready for a separate delivery process.
What proves quality
Current hashes, complete evidence coverage and zero open critical or high findings bind readiness to the reviewed learner bytes.

Linux Foundations: five topics, 21 learner artifacts, five source receipts, five QA paths and current dual-review evidence form one inspectable package.

Inspect package contents and exact checks
Package contents

Declared learner artifacts, labs and formative assessments stay together with current source, behavior and review evidence.

Owner

A content steward confirms internal consistency; independent reviewers retain responsibility for their own current rechecks.

Tools + checks

T04/T05 align declarations and files; T15/T17 bind source and video proof; T20 checks self-containment; T25 requires current independent review coverage.

Failure / return

Any correction that changes bytes makes affected evidence stale. Refresh only that proof, rerun affected checks and obtain a fresh same-role recheck where needed.

Verified

Independently reviewed
Education and technology evidence covers the same candidate; accepted findings have fresh rechecks.
Package ready
Declarations, checks and review evidence are complete and current for one exact learner-content package.

InputWhen curriculum or source intent is unclear
Example failure
The approved topic wording and the selected official source describe different versions of the same tool behavior.
Observable evidence
The curriculum pointer, source snapshot and cited official section cannot support one unambiguous learner claim.
Return stage
Input, where the content planner resolves scope and version before learner material advances.
Proof refreshed
The curriculum mapping, source snapshot, retrieval details and affected objective wording.
Resume when
One approved scope and source version support the intended teaching without guesswork.

Return stage
Design for the smallest affected topic; Input only if the approved curriculum must change.
Proof refreshed
The objective mapping, activity order, timing basis and intended formative check.
Resume when
Every activity traces to an approved objective and teaches required knowledge before practice.

Example failure
A learner page explains the right command but its practice control has no visible keyboard focus.

Return stage

Proof refreshed

Resume when
The corrected page remains accurate, works offline and passes applicable accessibility and behavior checks.

Return stage
Create, where the lab bundle or instruction is corrected; Verify then reruns the affected path.
Proof refreshed
The lab inventory, bundle digest, public tests, solved-run receipt and affected behavior checks.
Resume when
The clean learner bundle completes its declared path with authentic tools and all applicable checks pass.

ReadyWhen correction makes evidence stale
Example failure
An accepted correction changes a learner page after its source receipt and independent recheck were recorded.
Observable evidence
The evidence hashes name older bytes, so source and review coverage no longer apply to the current package.
Return stage
Verify for affected deterministic proof, then Review + improve for a fresh same-role recheck.
Proof refreshed
The source receipt, affected check results, reconciliation binding and reviewer recheck for the corrected exact bytes.
Resume when
Every required evidence record is current and the package has no open critical or high finding.
